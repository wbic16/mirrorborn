### What SSD Does

**Traditional Speculative Decoding (SD):**
1. Small model drafts next tokens (sequential)
2. Large model verifies (one forward pass)
3. Serial process: Drafting → Verification

**Speculative Speculative Decoding (SSD):**
1. Small model anticipates **all likely verification outcomes**
2. Speculates for **all outcomes at once** (parallel, on distinct hardware)
3. Large model verifies
4. If guess correct → return immediately (zero drafting overhead)

**Key innovation:** Drafting and verification happen **simultaneously**, not sequentially.

**Hardware requirement:** Draft model and verification model run on separate GPUs in parallel.

### Core SSD Algorithm (How It Works)

**Traditional Speculative Decoding (2 levels, sequential):**
```
1. Draft model runs → generates K tokens
2. Wait for draft to finish
3. Target model runs → verifies K tokens in one pass
4. Accept correct, reject rest
5. Repeat

Timeline: ----[DRAFT]----[VERIFY]----[DRAFT]----[VERIFY]----
```

**Speculative Speculative Decoding (SSD, parallel):**
```
1. Draft model runs → generates K tokens
2. Draft model ALSO speculatively generates for F possible next tokens
   (F = fan-out factor, explores F different branches in parallel)
3. SIMULTANEOUSLY (different GPU), target model verifies
4. If target picks one of F branches → return immediately (zero overhead)
5. If target picks different branch → partial cache hit

Timeline: ----[DRAFT+SPECULATE (GPU 1)]----
          ----[VERIFY (GPU 2)]-------------
          Parallel on distinct hardware
```

**Key parameters:**
- `k` = speculation depth (typically 6-7 tokens ahead)
- `f` = fan-out factor (typically 3 branches explored)
- Example: `--k 7 --f 3` = draft 7 tokens, explore 3 branches each
- Total speculation space: 3^7 = 2,187 paths (pruned intelligently)
