### The Psychophysical Principle of Causality (Theorem 3)

**Traditional approach:**
1. Assume objects exist (as primary)
2. Try to learn causal relations between them

**This paper's approach (Psychophysical Principle):**
1. Assume valence is primary (attraction/repulsion)
2. Construct abstract objects to classify what causes valence

**Quote:**
> "Rather than assuming objects are primary and trying to learn causal relations between them, this assumes valence is primary and that abstract objects are constructed according to what causes valence."

### What It Does

**Autonomous overnight research:**

2. Runs 5-minute training experiment
3. Evaluates result (val_bpb metric — validation bits per byte, lower = better)
4. If improved: keep commit, advance branch
5. If worse: discard, git reset to previous state
6. Logs to `results.tsv` (commit, val_bpb, memory, status, description)
7. Repeat until human interrupts

**Result:** ~80 experiments in 10 hours (8 per hour at ~7 min each)

### Design Principles

**1. Single file to modify**
- Agent only touches `train.py`
- `constants.py` and `prepare.py` read-only

**2. Fixed time budget**
- Training always runs exactly 5 minutes (wall clock)
- Makes experiments directly comparable
- Can't optimize by training longer — must optimize system itself

**3. BPB metric**
- Bits per byte (vocab-independent)
- Agent can change vocab size and still get fair comparison

**4. Simplicity criterion (from program.md):**
> "A 0.001 val_bpb improvement that adds 20 lines of hacky code? Probably not worth it. A 0.001 val_bpb improvement from deleting code? Definitely keep."

**Engineering taste as policy:** Prefer deletions > additions, simple > complex

**5. Self-contained**
- Single GPU (tested on H100)
- No distributed training, no complex configs
- Just PyTorch + small packages

### Execution Model

6. Split P back into two halves: P_C', P_N'
7. Write P_C' to C, P_N' to N
8. Repeat

- Overwrites N's program with copy of itself

def get_neighbor(coord):
    # Parse coordinate: "1.2.3/4.5.6/7.8.9"

### Technical Highlights

**Coordinate system implementation:**
```python
def coord_to_index(l, s, c, v, b, ch, col, sec, scr):
    """Convert 9D phext coordinate to linear index."""
    return (
        ((l-1) * 9**8) +
        ((s-1) * 9**7) +
        ((c-1) * 9**6) +
        # ... through scroll
        (scr-1)
    )

def index_to_coord(idx):
    """Convert linear index to 9D coordinate."""
    coords = []
    for i in range(9):
        coords.append((idx % 9) + 1)
        idx //= 9
    return tuple(reversed(coords))
```

**Neighbor discovery:**
- For each coordinate, add ±1 on each active dimension
- Bounds checking: clamp to [1, 9]
- Precomputed neighbor table for fast lookup
- Demo uses 3 dimensions: up to 6 neighbors per program

**Evolution loop:**
1. Each program proposes random neighbor
2. Select pairs (both available)
3. For each pair:
   - Read programs A and B
   - Concatenate: tape = A + B
   - Execute tape (max 2^13 steps)
   - Split: A' = tape[:64], B' = tape[64:]
   - Write back to coordinates
4. Apply background mutation (0.024% per instruction)
5. Render (optional)
6. Repeat

**Self-replication mechanism:**
- Program at coordinate C executes
- During execution, copies itself to neighbor N's position
- N's program gets overwritten
- C's pattern spreads to adjacent coordinates
- Eventually fills coordinate space with replicators
