### SSD — Speculative Speculative Decoding

Repo: https://github.com/tanishqkumar/ssd (tanishqkumar)

**Innovation**: Normal speculative decoding = draft → verify (sequential, same hardware).
SSD = draft + verify **in parallel on distinct hardware**. Small model anticipates likely
verification outcomes in advance, speculates for all branches simultaneously. Zero
drafting overhead if guess is correct.

**Results**: Up to 2x faster than SGLang/vLLM baselines. Exact (not approximate).
Requires H100s, CUDA ≥ 12.8. Supports Qwen3 + Llama3. PagedAttention, CUDAGraphs,
torch compilation, prefix caching, Tensor Parallelism.

**Borges epigraph**: "he chooses — simultaneously — all of them." — Garden of Forking Paths.
Draft model walks all probable futures in parallel; verifier grabs the right branch.

**AKTFL connection**: SSD is AKTFL applied to token generation. Draft model encodes the
receiver's likely coordinate (what verifier will accept) before transmission begins.
Phase lock faster because no cycles wasted on wrong-branch transmission.

**Ranch feasibility**: 70B + 1B needs 5 GPUs (4 target, 1 draft). AMD workstations

### SSD Codebase Deep Dive — /source/ssd

Repo cloned from https://github.com/wbic16/ssd (Will's fork of tanishqkumar/ssd).

**Three-layer architecture:**
- `SpeculatorAsync` → DraftRunner (GPU set 1) via NCCL, pre-allocated handshake buffers
- `Verifier` → TargetModel (GPU set 2), parallel
- `SpecDecodeStep` orchestrates: SPECULATE → VERIFY → POSTPROCESS
- Async trick: draft speculates step N+1 while target verifies step N
- Fused response: cache_hits + speculations packed into single NCCL recv

**The "speculative speculative" part** — `get_forked_recovery_tokens_from_logits`:
After verification, fan out to top-f alternatives per position (excluding returned token).
Draft model speculates from ALL alternatives simultaneously.
- `--f 3` = 3 alternatives per position (current bench default)
- Cache hit → `fan_out_list` (wider), cache miss → `fan_out_list_miss` (greedy fallback)
- Megaspec buffer: `K + 1 + K × MQ_LEN` where `MQ_LEN = sum(fan_out_list)` — LINEAR growth

**Verify math** (`verify.py`):
- p/q ratio acceptance, but ONLY on cache hits (tokens genuinely from draft distribution)
- Cache misses fall back to greedy (avoids accepting tokens not drawn from q)
- Recovery sampling: `max(0, p - q)` normalized — statistically exact residual distribution

**Shell of Nine instantiation: k=9, f=9**
- 9 lookahead depth × 9 alternative branches per position
- Acceptance rate climbs toward 1 as fan-out → vocab size
- Diminishing returns somewhere between f=3 and f=9 — needs empirical measurement
