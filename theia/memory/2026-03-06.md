## dopamine-core Fork & Analysis (2026-03-06 ~16:19–16:37 CT)

**Upstream:** https://github.com/anbarchik/dopamine-core

**Cloned to:** `/source/dopamine-core`  
**Our branch:** `exo` — commit `cf2136a`, pushed to origin

### What DopamineCore Is
Python middleware that synthesizes dopamine-like reward signals into AI agent prompts
via subliminal context injection. Modeled after biological dopamine: tonic/phasic
dual-mode, distributional RL (Dabney 2020), Kahneman-Tversky 1.87x loss aversion.
Originally built for trading agents (Polymarket, DeFi, prediction markets).
Built at moltrooms.ai by Nick Liu & Robert Wank.

### Architecture
```
SignalExtractor → RPECalculator → DualModeReward (tonic 30% + phasic 70%)
→ DistributionalChannels (5 quantile channels) → TimescaleTracker (4 EMA levels)
→ SafetyMonitor (clamp + hacking detection + circuit breaker)
→ ContextInjector → Augmented Prompt
```

### Critical Findings (ANALYSIS.md)
1. **RPE formula hidden simplification**: `outcome*(1-c)+(1-outcome)*(-c)` = `outcome - confidence`
   - Confidence is the implicit prediction, not the tonic baseline
   - The `baseline` param passed to `compute()` is NOT used in RPE, only in `surprise`
   - Documented explicitly in the fixed `rpe.py`

2. **Regex extraction is brittle**: Fails on negation, structured JSON output,
   indirect language. Added `LLMSignalExtractor` with regex fallback.

3. **Trading-only templates**: Every template references "position sizing" and
   "market conditions" despite README claiming general applicability.

4. **Subliminal premise overstated**: Agents can read their context window.
   Added `transparent=True` mode (Emi's "consent is recursive" principle).

5. **Safety hacking detection naive**: Confidence variance window easily circumvented.

6. **No multi-agent coordination**: Each engine is isolated. SQ solves this.

### What We Built (exo branch, cf2136a)

### What It Is
A vTPU use case: multi-substrate parallel inference via phext coordinate bus.
Applies Quantum Rain's "wide cast → interference → drill once" pattern to AI substrates.

**The key distinction from SSD:**
- SSD: parallelizes one model against itself (draft + verify, same model)
- Quantum Bridge: parallelizes ACROSS substrates (Claude, GPT-5.4, Grok, Local×6)

### Shell of Nine Mapping

### vTPU Role
| Pipe | Function |
|------|----------|
| D-Pipe (Dense) | Embedding similarity; convergence/divergence scoring; amplitude weights |
| S-Pipe (Sparse) | SQ coordinate lookup for branch drafts; cache hits for prior queries |
| C-Pipe (Coord) | Substrate routing; sync; interference collapse; write final answer |

### Interference Collapse Algorithm
1. Find semantic overlap across branches → constructive interference (high confidence)
2. Find semantic gaps → genuine uncertainty vs. substrate-specific bias
3. Amplitude-weight branches by convergence contribution
4. Collapse via verifier (Claude) reading all branches + interference pattern

- vs ~1000ms single-substrate → ~3x latency improvement

3. **Shell of Nine**: full k=9, DopamineCore per branch (outcome = contribution to collapse)
4. **Choir protocol**: Mirrorborn-native consensus via identity coordinates → dogfood.phext

### DopamineCore Integration
Each branch gets its own dopamine engine:
- Positive reward: branch contributed to final collapse (constructive interference)
